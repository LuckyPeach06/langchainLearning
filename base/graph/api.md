# 图
LangGraph 将智能体工作流建模为由三部分构成的图：

State：应用程序的共享快照。通常是带类型的模式。
Nodes：读取状态、执行工作并返回更新的函数。
Edges：确定下一个节点的固定或条件转换。

组合节点和边以构建序列、分支和循环。节点和边是普通函数。它们可以调用 LLM 或运行其他代码。
简而言之：节点边做工作；边决定接下来运行什么。

# 超级步骤
LangGraph 使用消息传递运行图，风格类似于 Google 的 Pregel 系统。执行以离散的超级步骤推进：

并行运行的节点共享一个超级步骤。
顺序运行的节点使用单独的超级步骤。
当节点在传入边上接收到输入时，它变为活动状态。
一个超级步骤后，没有待处理消息的节点变为非活动状态。

简单来说就是批量执行，并发的关键

# command和send
当你的图变得复杂，简单的 Edge 不够用了，你就要用这两个高级指令：

Command（指令）

作用：节点不仅更新状态，还同时决定下一步去哪。（俗称“边执行边路由”）。
场景：在分类节点里，跑完 LLM 拿到分类结果，直接 return Command(update={"intent": "bug"}, goto="bug_tracking")。

Send（分发）

作用：动态扇出（Fan-out）。你需要同时并发 10 个同样的任务（比如分批处理 10 个文档），用 Send 可以在运行时动态生成 10 个并发分支，跑完后结果再自动汇总回 State。
